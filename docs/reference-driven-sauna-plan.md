# Reference-driven parametric sauna plan

## Authority and scope

The supplied `reference of sauna 1.pdf` and `Modell 6-eck mit Glasfront 1.skp` are the design sources. The Holzsauna product page is useful for understanding the order of customer choices, but does not define this model's geometry or finishes. The first deliverable is **one six-sided, glass-front sauna family** whose width, depth, interior and equipment choices all derive from one construction model. Do not make a collection of unrelated whole-sauna GLBs, or scale a finished cabin uniformly.

The PDF has 14 photographic pages: pages 1–9 show the glass-front bench treatment, vertical end cladding, underside/support construction, floor, and heater. Pages 10–14 show a different interior arrangement with an infrared panel and optional lighting; those features must not silently become part of the six-sided model. A local parse of the SKP gives a source envelope of approximately **3013 × 3060 × 2292 mm**, an upper bench top at **1022 mm**, and a lower bench top at **619 mm**. Its named upper bench geometry spans approximately **2974 mm** in length and **975 mm** in depth. The model contains explicit glass, door, bench, backrest and wall geometry. These measurements are reference values, not a mesh to copy into the new model. The available Blender installation cannot import the original SKP directly, so the source was inspected with a local SKP parser; no file was uploaded.

The source plan's six corner points, in its own horizontal coordinates and metres, are approximately `(-19.889,-15.284)`, `(-19.889,-12.224)`, `(-17.589,-12.224)`, `(-16.876,-12.298)`, `(-17.589,-13.682)`, `(-18.769,-15.284)`. The ~2974 mm upper bench follows the first long wall. Recenter and rotate these before defining customer-facing width/depth; do not assume the raw SKP axes match the storefront's labels.

A direct render of the locally parsed SKP confirmed that edges 3 and 4 form the angled glass front. Edge 2, the short right section between the side wall and glass, is timber. The door is on edge 3. The browser and Blender construction use those edge assignments; `tools/blender/render_skp_reference.py` reproduces the source comparison view from the local GLB.

## Customer size choices

Offer explicit width, depth, and height selections in the cabin step. Proposed sizes are width **2400 / 2700 / 3060 / 3300 / 3600 mm**, depth **2400 / 2700 / 3013 / 3300 / 3600 mm**, and height **2100 / 2292 / 2400 / 2700 mm**. Mark 3060 × 3013 × 2292 mm as the measured reference. These are proposed manufacturing sizes until the producer confirms which combinations can be built and priced. The server must validate and price the selection before it can be saved; the viewer displays the resulting bench measurements beside the outer size.

Create three required `SINGLE` catalogue groups named `width`, `depth`, and `height`, with exactly one default option each matching the reference dimensions. Each option's code embeds its numeric millimetre value, for example `width-2400`. The existing option IDs, rules and price deltas then carry the choice through save and quote. Exclude combinations the manufacturer cannot make rather than relying only on a client constraint. Keep the model attribute dimensions equal to the default selections so detail pages, room checks and the first viewer frame agree.

At the measured reference size the long upper bench is **2974 mm** long and **975 mm** deep. A **680 mm** wide upper return continues along the right wall for **1208 mm**. The lower step is a separate **diagonal strip** below this L, not a straight bench across the glass face. At 2400 × 2400 × 2100 mm the long upper bench becomes **2314 × 820 mm**, the right return becomes **895 mm** long, and the diagonal strip scales with the available footprint. Upper support count changes from **6 to 5**. Width alone does not change seat height: at 2292 mm cabin height the upper/lower seat tops stay 1022/619 mm. A height choice moves those levels within safe bounds while keeping the 403 mm step.

The compact diagonal step now shortens along its run until its footprint clears the measured 480 × 420 mm heater envelope by at least 25 mm. This keeps the original 1398 × 675 mm step at the 3060 × 3013 mm source size and yields 862 × 535 mm at 2400 × 2400 mm. The 25 mm value preserves a visible physical gap; it is **not** a manufacturer-approved heater safety clearance. Heater model, guard and required clearances still need confirmation before these sizes can be sold.

## Single geometric model

Build the geometry **from scratch** as one parametric construction definition with a common coordinate system and named design parameters. Meshes may be grouped for rendering, but their dimensions and placement come from the same layout calculation. Never position a bench, heater or glass panel using an unrelated fixed transform. The SKP is a measurement/design reference, not the output mesh or a set of separate fixtures to place around a cabin.

Inputs: exterior width `W`, exterior depth `D`, exterior height `H`, interior finish, bench profile, heater choice, and lighting choice. Valid `W`, `D` and option combinations come from the catalogue. The source SKP supplies the reference values and dimensionless proportions for the six-sided outline, front facet angles, glass arrangement, door position and seat layout. The PDF supplies the seat profile, cladding, backrest, support and lighting appearance. Record every measured value and its source before implementing geometry. In the canonical orientation, **`W` follows the source's long upper bench wall** and `D` spans across the cabin; the source values are therefore `W₀ ≈ 3060 mm`, `D₀ ≈ 3013 mm`, `H₀ ≈ 2292 mm`.

Compute, in order:

1. `outerOutline(W,D)` from the SKP's corner/facet topology. Keep the facet angles and entry arrangement; move vertices according to the measured width/depth constraints. Reject dimensions that collapse a facet or leave insufficient room for the door.
2. `innerOutline = inset(outerOutline, wallThickness)`. Derive wall runs, glass planes, roof, floor and door opening from these same edges. Keep glass thickness and frame offsets as physical dimensions, not percentages of the cabin.
3. Keep the source's seating topology: one long upper run on the back wall, one 680 mm wide upper return on the right wall, and one diagonal lower step under the L. The return ends before the right wall/glass junction. Scale the diagonal step's measured four corners with the footprint, then verify that its entire envelope stays inside the outline and clear of the heater.
4. For each bench run, derive `seatLength = usableWallRun - endClearances`. **Width changes the usable wall run and therefore bench length.** At the reference size the long upper run is about 2974 mm inside a 3060 mm outer span: approximately 86 mm is consumed by wall/end clearances. Use the actual wall and end geometry to derive that 86 mm, then `benchLength(W) = W - leftClearance(W,D) - rightClearance(W,D)`. Recompute the slat count and support count from that length, while keeping individual slat width/gap near the reference. Preserve the photographed front edge and vertical end cladding. Avoid widening each board to fill the new room.
5. **Depth changes the available bench depth and walkway.** The source upper bench is about 975 mm deep at `D₀ ≈ 3013 mm`. Set `upperSeatDepth(D) = min(referenceSeatDepth, usableCrossCabinDepth(D) - requiredWalkway - heaterOrStepAllowance)`, with a lower valid bound established from the reference's seating ergonomics. The right return length follows the position of the upper front edge and the right wall/glass junction. The diagonal lower step changes both its length and width with the footprint. If a selected depth cannot fit the seat, step, doorway and heater clearances, reject that configuration rather than pushing geometry through a wall.
6. **Height changes the bench levels with the usable interior height.** Preserve the source headroom `H₀ - upperTop₀ ≈ 1270 mm` and the upper/lower difference `≈ 403 mm` where possible: `upperTop(H) = clamp(H - roofThickness - targetHeadroom, safeUpperMin, safeUpperMax)` and `lowerTop(H) = upperTop(H) - referenceStep`. Anchor backrests and lighting to the resulting upper bench, so their vertical positions move with it. Backrest segments, mounting gaps and LED lengths grow with the seat; their tops are checked against the ceiling clearance. These equations are construction rules to calibrate against the source, not guesses about fixed final ranges.
7. Place the heater in the free floor region near the source's measured centre at approximately `(0.35, 0.53)` m in canonical plan coordinates. Use its real envelope and required clearances. Recompute placement when dimensions, bench profile or heater choice change; reject configurations with no valid placement.

All dimensions are in millimetres at catalogue/API boundaries and metres in the renderer. The photographed details should be recognizable, but fine wood grain is supplied by materials rather than dense geometry.

## Asset and configuration flow

The catalogue database remains authoritative for allowed sizes, options and prices. The 3D source is a versioned parametric model package built from the SKP measurements and PDF details. Store its canonical visual assets and a default preview GLB in private S3, imported through the existing asset pipeline. CloudFront signed cookies provide browser access, with local object storage mirroring S3. The browser loads the package once and rebuilds the connected geometry from the selected dimensions and options; changing width or depth must not require a separate whole-sauna asset. Generated screenshots/AR exports may be cached by normalized configuration key in S3 later, if needed.

Represent width and depth as real catalogue selections, with server-validated numeric values and price deltas. Resolve the selected options into a typed `SaunaGeometrySpec`; avoid parsing display names or relying on the present `model_source=asset` fixed-GLB path, which ignores options. Include the geometry definition version in saved configuration previews so an old quote does not silently acquire a new shape after a model update.

The Blender construction script at `tools/blender/reference_sauna.py` exports GLBs and adjacent JSON measurement manifests at supported sizes. The browser now has a separate from-scratch renderer at `apps/web/src/three/reference/ReferenceSauna.tsx` using the same measured dimensions. Set a catalogue model's `model_source` attribute to `reference` to use it. Its width, depth and height option groups use codes such as `width-2400`, `depth-3013` and `height-2292`; the selected option IDs already pass through the existing server validation, pricing and saved-configuration paths. The next rollout gate is to create the new catalogue model and approved, priced size options, then compare browser screenshots against the Blender exports and PDF. The storefront must never show a locally resized preview while saving a different fixed-size configuration.

The browser's pure layout calculation is `apps/web/src/three/reference/layout.ts`. The renderer and the configurator's live measurement summary read that one result. A width selection changes the long run and its support count; a depth selection changes the upper seat depth and return length; a height selection changes both seat levels and their attached backrests. The 403 mm step stays fixed in the offered range. The Blender export remains an independent comparison of the same source measurements.

Current visual status: the measured footprint, upper L, diagonal lower step, backrest, glass and heater have been rebuilt from scratch and rendered at reference and compact sizes. The browser now applies wood grain at physical UV scale. Those grain maps are existing kit artwork, so colour, board profile, hinges and small joinery still need a closer PDF/SKP visual pass. The `reference-preview.html` development page and `scripts/reference-preview.cjs` regenerate the images in `docs/previews` for comparison. The preview GLB and parameter package have not yet been imported to private S3, and the new priced catalogue record has not yet replaced the demo models.

## Implementation order and acceptance

1. **Measure sources.** The initial local parse establishes the 3013 × 3060 × 2292 mm envelope and the two bench heights above. Extract the faceted outline, glass/door opening and bench support spacing more precisely from the parsed geometry; annotate the PDF features. Confirm any measurements the references do not establish with the owner.
2. **Geometry contract.** Define the typed parameter and constraint schema, allowed size range and invalid-combination errors. Build pure layout calculations before render meshes.
3. **One reference size.** Construct a new mesh from the measured parameters at 3013 × 3060 × 2292 mm. Compare exterior and interior screenshots with the SKP and PDF, including glass visibility and heater placement.
4. **Dimension sweep.** Test every offered width/depth pair and bench/heater combination. Check closed shell, valid glass and door opening, bench fit, support spacing, backrest fit, clear walkway and heater clearance. Visually review minimum, reference and maximum sizes.
5. **Catalogue/S3 integration.** Import the versioned visual package and preview assets, expose typed size selections, and connect them to configuration pricing and the viewer. Verify signed low/high asset access and loading on mobile.
6. **Retire old visuals.** After the new family passes review, remove the old procedural models and unused demo files from the live catalogue. Preserve historical model IDs and locked configuration/quote data. Delete unreferenced S3 objects only after a reference audit and retention period.

Acceptance: changing width changes the shell and every affected bench run; changing depth changes the facets, interior floor and affected benches; changing height preserves safe backrest/ceiling spacing; no bench or heater crosses a wall, glass plane or door zone; finish and lighting choices visibly affect the same model; price and saved configuration match the geometry shown.
